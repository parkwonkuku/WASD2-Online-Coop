# 문제 해결 사례

## 1. 여러 플레이어의 입력을 하나의 캐릭터에 안전하게 합치기

### 문제

모든 플레이어가 같은 캐릭터를 조작하지만 각자 사용할 수 있는 방향은 제한됩니다. 클라이언트에서만 키를 제한하면 변조된 요청이나 잘못된 상태로 다른 방향을 움직일 수 있습니다.

### 해결

1. 클라이언트가 로컬 배정 키만 입력 요청으로 변환합니다.
2. 서버 RPC가 요청한 Client ID와 룸에서 배정된 키를 다시 대조합니다.
3. 검증을 통과한 방향만 서버의 캐릭터 상태에 반영합니다.

### 결과

입력 편의성은 클라이언트에서 처리하면서 최종 이동 권한은 서버가 보장합니다. 2인·4인 모드가 같은 입력 경로를 사용해 인원별 분기는 키 배정 단계에만 남았습니다.

## 2. 공유 캐릭터 이동의 반응성과 네트워크 트래픽 균형

### 문제

위치를 자주 동기화하면 트래픽이 늘고, 간격을 크게 두면 원격 화면에서 움직임이 끊깁니다. 방향 전환은 즉시 전달되어야 했습니다.

### 해결

서버가 위치, 방향, 이동 가능 여부와 버전을 하나의 `ServerMoveState`로 관리했습니다.

- 방향 변경과 정지는 즉시 발행
- 이동 위치는 이전 발행 지점에서 일정 거리 이상 변했을 때 갱신
- Rigidbody2D 보간으로 화면 움직임 완화
- 클라이언트는 서버 상태를 기준으로 위치와 방향 적용

### 결과

중요한 입력 변화는 즉시 공유하면서 불필요한 위치 전송을 줄였습니다. 상태 버전으로 같은 좌표에서도 방향이나 이동 가능 상태의 변화를 구분합니다.

## 3. Lobby와 Relay의 생명주기 통합

### 문제

Lobby는 방 검색과 메타데이터를, Relay는 실제 연결을 담당합니다. 둘을 따로 처리하면 Host 이탈이나 참가 실패 시 검색 가능한 유령 방과 남은 상태가 생길 수 있습니다.

### 해결

`NetworkSessionController`에서 온라인 흐름을 통합했습니다.

- Host: Relay Allocation → Join Code → Lobby 생성 → heartbeat → Host 시작
- Client: Lobby 검색·참가 → Join Code → Relay 참가 → Client 시작
- 게임 시작 시 Lobby를 `InGame`으로 바꿔 검색에서 제외
- Host 종료 시 Lobby 삭제, Client 종료 시 자신을 제거
- Host 연결 해제 시 참가자를 로비로 복귀시키고 안내 표시

### 결과

온라인 서비스와 게임 씬의 수명을 한곳에서 관리해 실패 지점마다 일관된 정리 동작을 적용할 수 있었습니다.

## 4. 협동 기록의 순위표 중복 제거

### 문제

한 번의 협동 플레이가 참가자별로 제출되면 같은 팀 기록이 여러 줄로 보일 수 있습니다. Player ID만으로는 하나의 실행을 식별할 수 없습니다.

### 해결

게임 시작마다 모든 참가자가 공유하는 run ID를 만들었습니다. Leaderboards metadata에 run ID, 팀원, 맵, 인원, 시간과 충돌 횟수를 저장하고 조회 시 run ID 기준으로 중복을 제거합니다.

### 결과

협동 플레이 한 번이 순위표에서 하나의 팀 기록으로 표시됩니다. 맵과 플레이 인원별로 Leaderboard ID도 분리해 조건이 다른 기록끼리 경쟁하지 않게 했습니다.

## 5. 개인 최고 기록과 팀 순위 분리

### 문제

팀 전체 순위와 개인 진행 기록은 갱신 기준과 조회 목적이 다릅니다.

### 해결

- Cloud Save에는 맵·인원 조합별 개인 최고 기록 저장
- Leaderboards에는 팀 실행 결과와 참가자 metadata 제출
- 더 빠른 시간, 또는 같은 시간에서 더 적은 충돌만 개인 기록으로 갱신

### 결과

로비에서는 개인 최고 기록을 빠르게 보여주고, 랭킹 화면에서는 팀 단위 경쟁 기록을 별도로 제공할 수 있게 되었습니다.
