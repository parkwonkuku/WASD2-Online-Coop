# 우왕좌왕 미로: 2인·4인 협동 — 문제 해결 사례

기준: 2026-10-22 현재 개발 코드. [게임 소개](../README.md) · [아키텍처](architecture.md)

## 1. 여러 사용자의 입력을 한 캐릭터에 합치기

**문제:** 각 플레이어는 일부 방향만 담당합니다. 로컬에서만 제한하면 잘못된 방향 요청이나 중복·이전 라운드 명령이 실제 이동에 영향을 줄 수 있습니다.

**접근:** 호스트의 `HostMoveAuthority.Receive`에서 참가자와 배정 키, 순서 번호, Epoch, 이동 가능 상태를 확인합니다. 호스트 자신의 입력도 같은 검증 경로에 넣습니다. 이동은 틱 단위로 처리하며 같은 틱의 명령은 수신 순서에 따릅니다.

**구현 결과:** 키 배정과 명령 검증, 실제 이동 계산의 책임을 구분했습니다. 이는 입력 무결성을 위한 구현이며 모든 부정행위를 방지한다는 의미는 아닙니다.

## 2. 호스트 응답을 기다리지 않는 자기 입력 예측

**문제:** 호스트가 확정한 위치만 표시하면 자신의 입력에도 네트워크 왕복 대기가 생깁니다. 반대로 로컬 위치만 유지하면 다른 플레이어의 입력이 합쳐진 결과와 어긋납니다.

**접근:** `ClientMovePredictor`가 자신의 명령을 다음 로컬 이동 틱부터 적용합니다. 확정 상태를 받으면 처리된 명령을 제거하고 남은 자기 입력을 다시 계산합니다. 논리 위치와 화면 표시 위치는 `SharedCharacterView`에서 구분합니다.

**구현 결과:** 즉각적인 로컬 반응과 호스트 확정 기준을 함께 다루는 경로를 구성했습니다. 지연 감소율이나 화면 품질의 정량 개선은 별도 측정이 필요합니다.

## 3. 늦은 입력을 반영하면서 게임 판정 보호하기

**문제:** 늦게 도착한 방향 입력을 과거에 삽입하면 이미 처리한 별 수집·위험 지형·골인 결과까지 달라질 수 있습니다.

**접근:** 짧은 이동 이력에서 모든 플레이어의 입력과 충돌을 다시 계산하되, 이미 외부로 전달한 판정 경계 이전은 보호합니다. 재계산 경로에 새로운 판정 접촉이 생기면 되감기를 취소하고 현재 틱에서 명령을 적용합니다. 최대 0.2초 설정과 내부 최대 32틱 한도를 사용합니다.

**구현 결과:** 일반 이동 구간의 입력 시점 복원과 되돌릴 수 없는 게임 효과를 구분했습니다. 별·골인·효과음·기록을 클라이언트 예측에서 중복 실행하지 않도록 책임을 나눴습니다.

## 4. 씬 전환과 이탈에 맞춘 세션 수명

**문제:** 방 검색, Relay 연결, NGO 이벤트와 heartbeat가 서로 다른 수명으로 남으면 재참가나 종료 때 상태 정리가 복잡해집니다.

**접근:** 앱 전체의 `AppScope`, 한 번의 온라인 연결을 위한 `SessionScope`, 씬별 EntryPoint로 수명을 구분했습니다. 세션은 방 생성·참가 시 시작하고 종료 시 취소 토큰과 구독·주기 작업을 정리합니다.

게임 중에는 누구든 이탈하면 세션을 종료하고 로비로 돌아갑니다. 대기방에서는 참가자 이탈 시 호스트가 방을 유지하고, 호스트 이탈 시 참가자가 돌아갑니다.

**구현 결과:** 방을 나가는 정책과 자원 정리의 책임을 명확히 했습니다. 호스트 이전이나 자동 재접속 기능으로 설명하지 않습니다.

## 5. 랭킹 제출 실패가 개인 기록을 덮어쓰지 않게 하기

**문제:** 개인 기록과 팀 순위는 서로 다른 서비스에 저장됩니다. 순위 제출 실패를 전체 실패로 처리하면 이미 저장된 개인 기록까지 실패한 것처럼 보일 수 있습니다.

**접근:** `SubmitRunRecordUseCase`에서 인증, 프로필 저장, 개인 기록 저장, 리더보드 제출 순서를 명시했습니다. 앞선 저장이 실패하면 제출을 멈추고, 리더보드가 실패 결과를 반환하더라도 개인 기록 저장 결과를 유지합니다.

**구현 결과:** 개인 기록 보존과 순위 등록의 성패를 분리했습니다. 외부 저장소 사이의 원자성이나 모든 재시도 상황에서의 정확히 한 번 실행을 보장하는 구현은 아닙니다.

## 6. 체감 지연을 분석 가능한 구간으로 나누기

**문제:** 입력이 느리다는 체감만으로는 네트워크 왕복, 틱 대기, 화면 반영 중 원인을 구분하기 어렵습니다.

**접근:** 입력 발생·로컬 적용·화면 반영·호스트 확정 시점을 명령 식별자와 함께 기록하고 파일 로그를 구성했습니다. 애플리케이션 RTT와 Transport RTT도 구분합니다.

**구현 결과:** 서로 다른 기기의 재현 상황과 로그를 비교할 근거를 마련했습니다. 진단 도구 구성과 실제 성능 향상은 별개의 결과로 구분합니다.
